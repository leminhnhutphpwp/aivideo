# Environment Config Audit — Worklog

## Date
2026-06-04

## Overview
Performed a complete audit of all environment config files across the 3-layer architecture (web, backend, daemon). Found missing env vars, documented undocumented vars, and fixed consistency issues between `.env` and `.env.example` files.

## Trigger
Bug where `use-landing-settings.ts` used `NEXT_PUBLIC_API_URL` (non-existent) instead of `NEXT_PUBLIC_LARAVEL_URL` (the actual env var). This was already fixed; this audit prevents similar issues.

| Service | Files |
|---------|-------|
| **Web** | `apps/web/.env`, `apps/web/.env.example` |
| **Backend** | `backend/.env`, `backend/.env.example`, `backend/.env.docker`, `backend/.env.docker.example` |
| **Daemon** | `apps/daemon/.env`, `apps/daemon/.env.example` |

## Issues Found & Fixed

### 1. Web — Missing `NEXT_PUBLIC_SITE_URL` (⚠️ Documentation Gap)

**Used in**: `sitemap.ts`, `robots.ts`, `layout.tsx` (with fallback `'https://studio.wavise.com'`)

**Fix**: Added to both `.env` and `.env.example`:
```
NEXT_PUBLIC_SITE_URL=http://localhost:3000
```

### 3. Backend `.env.docker.example` — Missing `SIMULATION_MODE` (⚠️ Inconsistency)

`.env.docker` has `SIMULATION_MODE=true` (line 48) but `.env.docker.example` did not document it.

**Fix**: Added `SIMULATION_MODE=${SIMULATION_MODE:-true}` to `.env.docker.example`.

## Positive Findings

- ✅ **No `NEXT_PUBLIC_API_URL` references remain** — the original bug is fully purged

## Key Decisions

1. **`.env.example` should document ALL available vars**, not just required ones. This serves as developer documentation.
2. **Commented-out vars** (prefixed with `#`) are used for optional features (S3 storage, auth).
3. **`.env` and `.env.example` should always have the same keys** for the actual active configuration. Optional vars can be commented out in `.env` and uncommented as-needed.
4. Pre-existing backend test failures (4 of 120) are unrelated to env changes (Mockery mock setup, pricing data, AI compiler response).
